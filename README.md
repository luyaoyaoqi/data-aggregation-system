# 脉景问卷 · 数据采集系统

> 在线表单编辑器（类似 问卷星 / 金数据 / Typeform），面向非设计/技术背景的业务人员。
>
> 核心愿景：**5 分钟搭出专业表单**。所有设计/产品决策的最终衡量锚点。

---

## 当前状态

- ✅ `demo/` 已基本完工，可本地运行完整编辑器流程（搭建 → 预览 → 导出）
- ✅ 设计系统已定型：[`DESIGN.md`](DESIGN.md) + `demo/src/styles/tokens.less`
- ⏳ 未接：登录鉴权、表单数据持久化、多人协作、移动端适配、发布/分享链路

> 详细 demo 实现见 [`demo/README.md`](demo/README.md)。

## demo 后续走向 · 4 个方向

| 方向 | 适合场景 | 关键动作 | 投入 |
|---|---|---|---|
| **演示原型** | 内部演示、用户调研、BD 用 | 保留现状 + 部署静态站 | ⬇️ 最低 |
| **设计系统** | 多产品线复用、计划开源 | 抽 token + 组件 + 布局为独立包 | ⬆️ 中等 |
| **生产产品** | 正式上线、给客户用 | 拆 `editor-core` 包 + 业务壳 + 后端 + 协作 + 权限 | ⬆️⬆️ 最高 |
| **混合（推荐）** | 大多数真实情况 | 短期保留 demo 跑通流程 → 中期按反馈拆包 | ⬆️ 分阶段 |

## 推荐路径：混合（分阶段）

### 为什么不是一次性拆包？

- **demo ≠ 产品**：缺登录、协作、移动端、后端存储。直接拆 `editor-core` 包容易做错抽象（违反"不提前抽象"原则）。
- **真实需求未验证**：demo 还没被真实业务人员用过，先拆包投入大、风险高。
- **设计系统已有基础**：[`DESIGN.md`](DESIGN.md) 和 `tokens.less` 已落定，未来抽包是顺水推舟，但不必现在做。

### 分阶段动作

#### 阶段 1 · 用 demo 验证（1–2 周）

- 找 3–5 个真实业务人员跑通「搭表单 → 填表单 → 导出数据」全链路
- 记录卡点：操作路径、加载时机、协作场景、移动端表现
- 产出：可用性报告 + 下阶段决策依据

#### 阶段 2 · 决定下一步

根据阶段 1 反馈选择分支：

- ✅ **验证通过、要上线** → 进阶段 3a「做生产产品」
- ✅ **要复用、要开源** → 进阶段 3b「抽设计系统」
- ✅ **只是演示用** → 保留现状，打磨 demo 站即可

#### 阶段 3a · 生产产品

1. 拆分 `editor-core` 包（编辑器组件 + 状态机 + 数据模型）
2. 业务壳项目（路由、权限、API、协作）
3. 后端：表单定义存储、提交数据存储、统计导出
4. 移动端适配 / 移动端填表体验优化

#### 阶段 3b · 设计系统化

1. 抽 `tokens` 包（CSS 变量 + UnoCSS preset）
2. 抽 `components` 包（按 `CardTabs` / `QuestionCard` / `PropertyPanel` 等维度）
3. 文档站（参考 `demo/preview/d5.html` 模式）
4. 发布到 npm / 内部包仓库
